# 给另一台电脑 Codex 的提示词：DINOv3 ACT 同步五步块推理

以下正文可以直接复制给目标电脑上的 Codex。

---

请在这台电脑现有的 **DINOv3 视觉骨干 ACT** 工程中，实现“同步五步动作块、零噪声”的仿真推理调度。参考仓库是：

- 仓库：https://github.com/luke711-xyy/act-ur10-sweep-sim
- 参考分支：`feat/pac-act-posttraining`
- 本提示词对应的实现提交：`c7d63594943ad55ea4e997559a8182e8d6cd74ab`
- 这是 **调度移植任务**，不是把 DINOv3 模型替换成该分支的 ResNet 模型，也不是开始 PAC-ACT / PPO / SAC 训练。

## 一、先检查本机真实状态

先读取本机工程说明，确认当前工作目录、分支、未提交修改、DINOv3 checkpoint、观测预处理、动作归一化统计，以及真实运行中的推理与训练进程。保留用户现有修改，不停止其他任务。

可以 fetch 参考分支并通过 `git show <提交>:<文件>` 阅读；**不要直接切换到参考分支、合并整个分支或覆盖当前 DINOv3 工程**。该参考分支包含大量与本任务无关的 ResNet / PPO 实现。

重点核对这些文件中的实现，而不只阅读说明文档：

1. `pac_act/hybrid.py`：`BlockClock`、`integrate_xy_yaw`、`HybridEpisode._execute_block`，了解五步块边界、连续参考、100 Hz 控制子步和 Z 所有权。
2. `pac_act/lifecycle.py`：`Collection.block`，了解“观测→同步预测→执行前五步→重新观测”的顺序。
3. `scripts/evaluate_new_schedule_batch.py`：零噪声、无学习的实际评测调用方式；不要照搬其中的本机路径、批次清单或模型加载器。
4. `pac_act/policy.py`：仅参考 `means` 取前五步和反归一化的动作接口；其中 `ChunkPolicy` 明确限定 ResNet，**不能直接用于 DINOv3**。
5. `tests/test_pac_bridge.py`、`tests/test_pac_execution.py`、`tests/test_new_schedule_batch.py`、`tests/test_pac_Z_audit.py`：参考时钟、积分、终止、Z 隔离和评测记账测试。

先报告本机调度与参考实现的具体差异。如果本机没有 A*→ACT Hybrid 或控制配置与下述约束不同，明确指出，先询问，不擅自补齐或更换整套控制器。

## 二、只改推理调度

实现一个可显式选择的新调度入口，保留原入口作为对照：

- 动作频率 **25 Hz**。
- 每次使用当前观测，同步运行现有 DINOv3 ACT，生成原有的 **25 步动作块**。
- 明确执行该块的 **索引 0、1、2、3、4**，共 **5 步 / 0.20 秒仿真时间**；剩余 20 步不执行、不转入下一块。
- 五步执行完，取得最新观测，再预测下一块；始终使用新块的前五步。
- **取消跨块 temporal ensembling / 时序集成**：不对历史动作块加权融合，也不按旧异步预测时间戳选取块内较后的动作。
- 同步推理期间，MuJoCo 物理和控制时钟均不推进。不能因为模型计算耗时而跳动作、补跑物理帧或累积过期预测。
- 不需要 `sleep(0.20)` 实现块周期；周期由实际执行的五个 25 Hz 动作决定。图像采集也不能额外推进物理。
- 不在块边界停刷、插入 hold、重置速度、导纳或动作积分参考。保留原生增量积分、每个动作四个 100 Hz 控制子步与指令连续性。
- 保留机器人状态历史的逐动作更新；不是五步都使用同一份过期状态。
- 若块内已经达到原生终止条件，仅执行实际前缀，立刻终止，不能强行补满五步。
- 决策等待不消耗仿真帧预算，但所有已执行物理动作照常计入预算。

**零噪声**指使用原模型确定性推理输出，模型设为推理模式；不加高斯探索、残差、随机偏移，不更新任何权重。不要为了移植调度而删除 CVAE 模块、重建网络、重置 DINO 投影层或改变正常推理潜变量路径。

注意核对动作单位：本参考的动作接口是反归一化后的 `(dx, dy, dz, dyaw)` 增量，不是绝对位姿或速度。必须根据本机真实接口正确连接，只反归一化一次，并保留原生积分参考的定义。若本机动作契约不同，先说明适配方式，不能直接套公式。

## 三、严格保留 DINOv3 与 Hybrid 控制

以下内容不属于本次调度改造：

- 保留本机 DINOv3 权重、视觉特征提取、投影、相机数量与顺序、图像预处理、机器人状态与目标数量输入、动作归一化统计。
- 不加载参考分支的 ResNet `step_100000` 来替换 DINOv3；使用本机已经确认的 DINOv3 ACT checkpoint，并记录其身份。
- 保留 A* 的选件、落刷位置、前段运动、寻找接触和稳定后交接规则；不增加物理候选筛选、恢复路线或失败重试。
- 保留首次有效 ACT 动作起的 **2 秒缓启动**；DINO 零噪声方案在这两秒及之后均使用同一个 DINOv3 checkpoint，不需要在两秒后切到另一个 PPO Actor。不要把参考分支“冻结 ACT→学习 Actor”的训练分工搬过来。
- **Z 始终由腕部力导纳和现存有界实际 Z 跟随补偿管理，不能执行 ACT 预测 Z。** 不使用桌面接触力真值替代腕部传感器。
- 不改控制增益、滤波、IK 精度、速度限制、工作空间或安全保护，不在模型查询或块切换时重置这些状态。
- 保留整回合共享的 **2000 个 25 Hz 动作帧 / 80 秒仿真时间**预算，包含 A* 前段、接触寻找和 ACT；首次入区后 **2 秒终止窗口**跨阶段、跨动作块连续，不重置。
- 保留原生严格成功判定，不把“最终数量匹配”直接改称严格成功。

参考实现使用的 trial-4 有效配置为：目标力 1 N，总 Z 修正 ±2 mm，寻找接触 M/B/K=10/400/10、维持接触 10/800/10；实际高度 1 mm 启用导纳，腕力 0.5 N 持续 0.1 秒确认接触，0.8–1.2 N 持续 0.2 秒后交 ACT XY / yaw；首次有效 ACT 动作后两秒保留现有缓启动，之后恢复原生动作处理。**这些用于核对控制版本，不授权你在目标机器上顺便调参。** 若有差异，先列清楚。

本任务仅针对仿真。“推理期间暂停仿真时间”不能直接移植到真实机械臂的实时控制线程。

## 四、测试与真实验收

先补单元 / 集成测试，至少覆盖：

1. 单次预测恰好使用前五步；下一次查询发生在五个已执行动作后，历史块不参与融合。
2. 模拟很慢的模型推理，模型计算前后仿真时间不变；不丢失首步、不跳到块后部。
3. 增量只反归一化和积分一次；块间参考与 100 Hz 插值连续，不新增停顿或复位。
4. 输入相同观测时，调度改造前后的单个 DINOv3 动作块输出一致；checkpoint 和归一化统计哈希不变。**整条轨迹不要求与旧时序集成方案相同。**
5. 把 ACT 的 Z 预测改成极大值，也不能改变 Z 执行；相同物理传感输入下 Z 控制计算保持原样。
6. 两秒缓启动、2000 帧共享预算、首次入区两秒窗口、块内提前终止和安全终止均不被块切换破坏。

测试通过并确认本机推理资源空闲后，做小规模真实 DINOv3 ACT 仿真验收：

- 预登记两个新布局，分别 target 1、target 6；每个布局用旧调度和新零噪声调度各执行一次，初始物理布局一致。
- 每个“布局×调度”只有一次机会，不失败重试、不换 seed、不只保留成功。IK / 安全失败也保留已经测得的实际收集数量；未知数量保留未知，不能填零。
- 保存对照视频、腕力曲线、Z 跟随误差、真实收集数量、原生严格成功与终止原因，以及实际查询 / 块索引 / 物理帧计数日志。
- 视频应从真实执行或保存物理状态回放生成，不能为了补视频重新执行该次机会。
- 只汇报观察到的结果，不能把两个布局的改善称为统计显著提升，也不能把 ResNet 分支的评测结果当成 DINOv3 的结果。

完成后交付改动文件、具体调度差异、测试结果和物理验收证据。**先汇报，不启动训练或 120 布局批测，不改写旧评测记录；也不自行推送或合并其他分支。** 如果实际验收条件不足，保留实现和测试，明确说明尚未做真实 rollout。
